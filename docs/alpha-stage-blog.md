# 《仓鼠盒》Alpha 冲刺阶段测试报告与软工实践总结

仓鼠盒是一个本地优先的多媒体收藏管理工具。用户可以建立作品条目，关联硬盘中的图片、视频、电子书、游戏等资源，再通过标签、1 至 10 分评分和关键词检索整理收藏。

Alpha 阶段的主要任务是把“功能已经实现”推进到“模块能够测试和交付”。本阶段完成了数据、条目资源、标签评分、检索、适配器、Windows 安装和分享包原型等模块，并建立了分层测试、CI 和安装验证流程。

## 一、Alpha 阶段概况

最新主线全量测试结果为：

```text
161 passed, 1 xfailed, 111 warnings
```

唯一的严格预期失败对应 `FallbackAdapter` 重复注册问题，团队已经将该问题登记为真实缺陷。成员五的分享包独立分支完成专项 `53 passed`，分支全量为 `214 passed, 1 xfailed`。

从模块结果看，数据层专项 65 项、条目与资源 51 项、标签与评分 47 项通过；检索模块有 15 个相关用例，组合查询性能满足当前规模；Windows 安装程序构建成功，并在 3 台同版本 Windows 11 设备上完成安装、启动和卸载。

因此，Alpha 的**核心模块和课程交付基本完成**，已经具备稳定的后端开发、测试、构建和演示基础。前端真实联调、桌面原生桥和分享包用户闭环属于下一阶段优先补齐的部分。

## 二、Version Alpha Bug List

### 2.1 已解决的主要问题

| 模块 | 问题 | 处理结果 |
|---|---|---|
| 数据迁移 | 中文 Windows 下迁移配置编码错误 | 改为纯 ASCII 配置 |
| 数据迁移 | 日期字段在带数据升级时写回失败 | 迁移中保留原文本值 |
| 数据迁移 | CI 环境中的 Windows 盘符转义触发插值错误 | 直接传递数据库 URL 对象 |
| 数据约束 | 删除标签时错误级联删除评分关系 | 改为 RESTRICT，引用中禁止删除 |
| 标签评分 | 分类与标签的唯一性作用范围混淆 | 拆成分类全局唯一和分类内标签唯一 |
| 分享包 | 旧 Schema 使用 5 分上限和持久标签 ID | 统一为 1 至 10 分和临时 `tag_ref` |
| 分享包 | 评价错误地保存在标签关系上 | 改为条目级 `source_review` 与 `share_review` |
| 发布 | PyInstaller 未加载后端入口 | 增加隐式导入并恢复窗口模式 |

这些问题说明，数据迁移、Windows 环境和打包流程不能只依赖开发机上的正常场景，必须用临时老库、CI 和安装制品反复验证。

## 三、场景测试

### 场景一：整理并找回一部作品

**典型用户：** 小李

**用户需求：** 小李收集了电影、字幕和封面，希望把它们整理成一个作品，并能按标题、标签和评分快速找回。

**操作过程：**

1. 新建“电影”类型条目并填写标题；
2. 关联视频、字幕和封面；
3. 创建“科幻”标签，设置为 9 分；
4. 输入标题片段，并按标签和评分筛选；
5. 将文件移出原位后重新检测，再恢复文件；
6. 将条目移出库，确认原始文件没有被删除。

**测试结果：** 条目 CRUD、资源关联、缺失检测、恢复、解除关联和移出库均通过自动化测试。中文关键词、单标签、多标签、评分区间、排序和分页在后端通过。移出库不会删除用户磁盘文件。

**阶段边界：** 前端目前仍以演示数据为主，界面完整点击流程尚未与真实接口完成验收。

### 场景二：关联多种资源并安装桌面版

**典型用户：** 小王

**用户需求：** 小王经常收集不同类型的文件，希望系统能识别文件类型，并在 Windows 上直接安装使用。

**操作过程：**

1. 关联图片、视频、电子书和未知 `.xyz` 文件；
2. 查看类型识别和元数据；
3. 使用系统默认程序打开资源；
4. 尝试打开 `.exe`、`.bat` 等危险文件；
5. 在 3 台 Windows 11 电脑上安装、启动和卸载应用。

**测试结果：** 成员七记录图片、视频、电子书、未知类型和危险后缀场景正常；适配器注册表仍有严格 xfail。Windows 安装程序在 3 台 Windows 11 家庭版 23H2 设备上完成安装、启动和卸载，后端连接正常。

**阶段边界：** 三台设备系统版本相同，跨 Windows 版本兼容性和卸载残留仍需后续补充；桌面桥尚未完成界面联调。

### 场景三：导出并预览分享包

**典型用户：** 小陈

**用户需求：** 小陈想分享作品标题、标签、评分和评价，同时保留本机原始文件。

**操作过程：**

1. 选择两个带标签评分的条目；
2. 导出 `.hbox` 元数据包；
3. 检查包内标签引用、评分和资源 SHA-256；
4. 在接收端执行只读预览；
5. 使用包含路径穿越的异常压缩包验证安全边界。

**测试结果：** 分享包专项 53 项通过。两个条目、10 分和空评分可以正确导出；标签使用临时 `tag_ref`；ZIP 不包含原始媒体和本地路径；缺失资源会标记为 `missing`；预览不写数据库，并能拒绝路径穿越等异常输入。

**阶段边界：** 当前验证属于函数级原型，尚未接入 HTTP、分享页面、保存对话框、正式导入、冲突处理和跨设备导入。

## 五、Alpha 版本出口条件

项目进入 Alpha 时，最初希望界面完整、功能链路全部打通。随着开发推进和截止时间接近，团队按功能优先级调整了出口：先保证核心模块能够运行，再保证数据安全，最后保证程序可以安装和回归测试。

本阶段最终采用的出口条件是：

1. 已实现模块能够稳定自动化回归；
2. 数据迁移不损坏条目、资源、标签和评分；
3. 用户原始媒体文件不会被误删；
4. Windows 安装程序可以启动并连接后端；
5. 测试报告能够区分自动化通过、手工记录和未执行场景。

对照以上条件，团队已经完成 Alpha 阶段的主要开发与交付工作：核心后端模块通过回归，数据安全和安装链路有实际证据，测试报告及软工学习总结完整。

Alpha 的完整用户闭环仍需继续完善。前端真实接口、桌面桥、条目整体评价和分享包正式导入将作为下一阶段重点工作，而不是本阶段已经完成的成果。

## 六、习得的软工原理/方法/技能

### 6.1 契约先行与单一事实来源

团队先确定字段、接口、错误码和评分范围，再并行开发。标签评分统一为空值或 1 至 10 的整数，分享包使用临时 `tag_ref`，条目只保存一份整体评价。契约减少了各模块自行解释字段的空间。

### 6.2 单一职责与关注点分离

条目服务负责业务编排，仓储负责数据库，适配器负责文件识别，桥接层负责系统能力，发布模块负责打包。职责拆清后，每个模块可以独立测试和替换。

### 6.3 开闭原则与安全边界

新增文件格式通过实现适配器并注册进入系统，核心分发逻辑无需修改。分享包按不可信外部文件处理，只读预览不解压到磁盘、不写数据库，并拒绝路径穿越等异常输入。

### 6.4 测试分层与证据意识

团队使用领域、应用、API、数据库、端到端和发布测试覆盖不同风险，并明确区分自动化通过、成员手工记录和未执行场景。类型检查和 Mock 数据不能替代真实接口验收。

### 6.5 幂等、边界值、可追踪与可重复构建

条目标签关系使用幂等更新，评分覆盖 `null`、1、10、0、11、小数和布尔值。Issue、PR、提交和报告形成追踪链，CI 和 Windows 每日构建降低环境差异。

| 成员 | 主要软工收获 |
|---|---|
| 成员一 | 用迁移、约束和备份测试保护数据安全；用真实环境发现编码和版本兼容问题 |
| 成员二 | 用应用服务划分文件、仓储和系统调用边界；用端到端测试验证资源生命周期 |
| 成员三 | 契约先行、幂等更新、边界值分析和跨模块错误码设计 |
| 成员四 | 用分层查询和基准数据控制性能；用白名单和稳定排序处理分页 |
| 成员五 | 用可校验格式约束分享数据；在只读边界内处理不可信压缩包和异常输入 |
| 成员六 | 用类型检查和构建守住静态质量；认识到静态通过不能替代真实交互 |
| 成员七 | 用适配器与策略模式扩展文件格式；用最小权限保护系统调用边界 |
| 成员八 | 用 CI、每日构建和安装验收把代码转化为可运行制品 |

本轮 Alpha 冲刺的主要成果，是把各模块从独立代码推进到可测试、可构建、可追踪的阶段。下一阶段将在现有基础上补齐用户操作链路、自动化界面测试和分享包正式导入，使软件从“核心功能基本完成”进一步达到“完整用户流程验收通过”。
