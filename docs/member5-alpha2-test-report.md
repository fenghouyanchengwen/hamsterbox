| 项目 | 内容 |
|---|---|

| 运行时 | Python 3.11.15 |
| 主要依赖 | pytest 8.4.2、JSON Schema 校验库 4.26.0、SQLAlchemy 2.1.8、Pydantic 2.14.3 |
| 数据与文件 | SQLite 内存测试库、pytest 临时文件、内存中的 ZIP 和示例 manifest |
| 测试分支 | `feature/member5-share-preview`，提交 `1613512`；包含导出原型与规范草案 |

| 执行命令 | 专项：`python -m pytest tests/application/test_share_export.py tests/application/test_share_schema.py tests/application/test_share_preview.py -q -p no:cacheprovider`；全量：`python -m pytest -q -p no:cacheprovider` |

测试分三层：

1. **格式与边界检查**：用 JSON Schema 校验单条目和多条目示例，检查评分边界、条目类型、评价模式与标签字段。
2. **导出与只读预览自动化测试**：使用临时 SQLite 库与临时文件，检查元数据包、资源指纹、缺失文件、路径、压缩包结构及封面警告。
3. **后端回归测试**：在成员五预览分支执行全量后端用例；与团队已知问题对照，不把预期失败算成通过。

当前结果：分享包专项测试 **53 项通过**；该分支全量后端测试 **214 项通过、1 项预期失败、1 条警告**。预期失败是团队已有的 `FallbackAdapter` 重复注册问题，不属于分享包实现。全量数字包含专项测试，不应与 53 相加。

**方法局限（必须说明）**：以上结果只覆盖成员五独立分支的自动化测试；三个分享包 PR 均未合入 `main`。导出尚未接入前端、HTTP 接口和桌面保存对话框；只读预览也未接入界面或写库导入。本次未进行 Windows 桌面手工操作、跨设备导入、冲突处理或真实用户数据测试。测试环境为 macOS / Python 3.11，与项目计划使用的 Windows / Python 3.12 不同，不能替代目标环境验收。

## 二、Bug List（v1.0）

### B1　分享包旧草案评分上限为 5，与团队 1 至 10 分契约不一致

- **现象**：旧草案提交 `bcd6f60` 中，Schema 的 `rating.maximum` 为 5；团队契约允许 1 至 10。
- **验证方式**：对比旧版 `docs/share-package-v1.schema.json` 与主线 `docs/tag-rating-contract.md`；对修订版执行评分边界测试。
- **影响**：高。按旧草案校验时，6 至 10 分无法正常表示。
- **原因**：草案早于标签评分契约冻结，未及时同步。
- **状态**：已在规范草案提交 `efa6733` 中改为 1 至 10；专项测试覆盖 1、10、`null`、0、11、9.5 和布尔值。PR #12 尚待评审；`1.0` 的严格整数问题另见 B5。
- **归属**：成员五；契约对照成员三。

### B2　旧草案要求标签持久分享 ID、颜色和评分开关

- **现象**：旧 Schema 要求标签携带 `share_id`、`color`、`rating_enabled`，条目关系使用 `tag_share_id`；团队契约要求包内临时 `tag_ref`，不分享本地分类及颜色。
- **依据**：`docs/tag-rating-contract.md` 第 7.2 节；旧草案提交 `bcd6f60`。
- **影响**：高。旧字段无法直接对应现有标签模型，也会混入本地分类信息。
- **状态**：PR #12 中已改为包内 `tag_ref`，并禁止旧标签字段；预览原型另对引用缺失和重复进行检查。标签导入时选择本地分类仍未实现。
- **归属**：成员五；与成员三确认。

### B3　旧草案把评价放在标签关系上

- **现象**：旧 Schema 要求 `entry_tags` 带 `review`；团队契约规定条目只有一份整体评价，分享时区分 `source_review` 和 `share_review`。
- **影响**：高。原评价和分享评价无法按团队约定表达，可能导致后续联调中评价语义混乱。
- **状态**：PR #12 已移除标签关系中的 `review`，增加 `review_mode`、`source_review`、`share_review`；示例覆盖三种模式。导出原型目前只实现 `original` 模式。
- **归属**：成员五；条目评价 API 需成员二配合。

### B4　示例条目类型曾使用中文值，与共享枚举不一致

- **现象**：旧示例使用 `游戏`、`电子书`，而后端 `EntryType` 使用 `game`、`book` 等英文值。
- **影响**：中。示例不能直接与后端条目模型对齐。
- **原因**：本人成员五草案在中文化时把机器字段的取值也改成了中文。
- **状态**：PR #12 已把示例改回 `game` / `book`，中文用于标题和说明；专项测试确认中文类型值被 Schema 拒绝。
- **归属**：成员五。

### B5　预览对浮点形式的整数评分 `1.0` 校验不严格

- **现象**：把有效分享包的 `entry_tags[0].rating` 改为 JSON 数值 `1.0` 后，`preview_share_package` 返回预览，没有报错。
- **验证方式**：2026-11-16 使用单条目示例，将评分改为 `1.0`，在内存中生成 ZIP 并调用预览函数，结果为接受。该测试与已有 `9.5` 被拒绝的专项用例不同。
- **预期**：与团队 `StrictInt` 约定一致，仅接受 `null` 或整数；应拒绝 `1.0`、9.5 和布尔值。
- **原因**：当前依赖 JSON Schema 的 `integer` 校验；该校验接受数值上等于整数的浮点数，而预览语义检查未再检查 Python 值的严格类型。
- **影响**：中。预览与标签评分 API 的输入约束不一致；目前正式导入尚未实现，不能推断已有数据库受影响。
- **状态**：已复现，**未修复**；需在预览语义校验中增加严格类型检查，并补充 `1.0`、`10.0` 和布尔值回归测试。
- **归属**：成员五。

### B6　来源资料库标识尚无确认的持久化方案

- **现象**：草案要求 `source_library_id`；导出函数要求调用方传入合法 UUID，但主线尚未确认该标识的创建和持久化方式。
- **影响**：高。调用方若每次临时生成，会导致来源标识不稳定，影响后续重复导入识别。
- **状态**：未解决。原型校验 UUID 格式，但不生成或保存稳定资料库 ID；需先与成员一、二确认再接入真实调用链。
- **归属**：成员五 + 成员一、二。

### B7　分享包功能尚未接入界面和桌面保存流程

- **现象**：导出函数返回 ZIP 字节，预览函数接收 ZIP 字节；目前没有相应的分享包 HTTP 路由、前端操作页面或保存对话框调用链。
- **影响**：高。自动化测试可调用函数，但普通用户暂时无法通过应用界面完成分享。
- **状态**：未实现，PR #37 和 #39 均为草稿；需要接口、界面与桌面桥联调。
- **归属**：成员五 + 成员六、八。

### B8　封面、部分资源与分享评价模式尚未完整实现

- **现象**：导出原型当前将 `cover` 写为 `null`，只支持完整正式条目、全部关联标签和 `original` 评价模式；部分资源的临时派生条目尚不可用。
- **影响**：中高。当前导出原型不能覆盖团队契约中的全部分享需求。
- **状态**：未完成。预览会对包内封面进行大小、哈希、类型和文件头检查，但文件头检查不是完整图片解码；封面策略及临时条目的创建、保存、清理仍待确认。
- **归属**：成员五 + 成员二、三、六。

### B9　正式导入、冲突处理和跨设备匹配尚未实现

- **现象**：只读预览能解析和校验分享包，但尚不扫描接收方文件、不执行 SHA-256 匹配，也不写入数据库或处理导入冲突。
- **影响**：高。尚无法完成“设备 A 导出、设备 B 预览并导入”的用户闭环。
- **状态**：未实现；需确认重复导入、标签分类选择、事务回滚和跨设备资源匹配规则，并补充实际设备测试。
- **归属**：成员五 + 成员一、二、三、八。

## 三、场景测试

以下用例区分**自动化通过、已复现问题与未实测**。自动化测试使用临时数据，不等同于用户在桌面界面完成操作。

### 场景一：导出两个带标签评分的条目

| 项目 | 内容 |
|---|---|
| 典型用户 | 想把自己整理的两个作品介绍分享给同伴的用户 |
| 用户需求 | 分享标题、标签、评分和评价，同时保留自己硬盘上的原始文件 |
| 前置条件 | 临时 SQLite 测试库有两个正式条目、一个测试资源和一个共享标签 |
| 操作步骤 | 1. 创建临时测试数据；2. 调用 `export_share_package`；3. 读取生成 ZIP 的 `manifest.json` |
| 预期结果 | 两个条目、10 分与空评分正确写入；同一标签引用一致；不包含原始文件和资源路径 |
| 实际结果 | **自动化通过**（`test_exports_two_entries_with_fresh_hash_and_without_private_data`）；资源的 SHA-256 与临时文件实际内容一致 |
| 备注 | 原型返回字节，尚无界面选择和保存文件操作；用户自由文本仍可能自行包含敏感信息 |

### 场景二：预览有效分享包

## 四、性能基线

| 指标 | 实测 |
|---|---|
| 分享包专项测试 | 53 项通过，pytest 报告耗时 0.59 秒 |
| 本分支后端全量测试 | 214 项通过、1 项预期失败，pytest 报告耗时 2.45 秒 |
| 单条目示例 ZIP | 752 字节；预热后内存预览 100 次，平均 7.41 毫秒、最大 8.19 毫秒 |
| 10 条目示例 ZIP | 1271 字节；预热后内存预览 100 次，平均 8.97 毫秒、最大 10.19 毫秒 |
| 压缩包保护上限 | 草案实现中压缩包 50 MiB、manifest 10 MiB、单张封面 5 MiB；这些是限制值，不是性能测试结果 |

结论：在本机和小型合成示例下，只读预览完成速度可作为初始参考。测试包不包含封面或原始媒体，100 次调用在同一 Python 进程内进行；每次调用包含读取和校验本地 Schema。该结果不能代表大分享包、低性能电脑、Windows、真实磁盘读写或跨设备传输性能。大文件 SHA-256 计算、包含封面的大包、并发和真实设备性能均未测试。

## 五、Alpha 出口条件

从分享包模块出发，本阶段建议的最低出口是：

1. 分享包规范、Schema 和示例与团队条目、标签及评分契约一致，并经相关成员评审；
2. 评分 `null` 和 1 至 10 的严格整数均可正确处理，非法值被拒绝；
3. 可从实际界面选择条目并导出，包中默认不包含原始媒体及本地路径字段；
4. 接收方可预览条目、标签、评价与资源状态，异常包被安全拒绝，确认前不写库；
5. 冲突和资源缺失有清晰处理方式，确认导入后事务成功或完整回滚；
6. 至少完成一次真实跨设备导出、预览与导入，并保留测试记录。

当前**尚未达到完整出口**：第 1 条仍待评审，B5 使第 2 条不满足；第 3 至 6 条的界面、正式导入、冲突处理和跨设备验证尚未完成。函数级导出与只读校验已具备专项测试证据，不能代替完整用户场景验收。
