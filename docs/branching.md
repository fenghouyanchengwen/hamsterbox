# 分支与提交规范

## 分支模型

只保留 `main` 一条长期分支，所有开发使用短生命周期分支。

```
feature/<模块>-<简述>
fix/<模块>-<简述>
docs/<文件名>
```

分支创建前先更新 `main`：

```powershell
git checkout main
git pull
git checkout -b feature/tag-rating
```

## 提交信息

格式：`<类型>: <说明> (#Issue编号)`

| 类型 | 用途 |
|---|---|
| feat | 新功能 |
| fix | 修复缺陷 |
| docs | 文档 |
| test | 测试 |
| refactor | 重构 |
| chore | 构建、依赖和杂项 |

示例：`feat(tag): 支持评分区间筛选 (#12)`

## 拉取请求

- 一个 PR 只完成一个 Issue。
- 描述包含关联 Issue、改动内容、验证方式和界面截图。
- 至少一名其他成员评审。
- 统一使用 Squash merge。
- 合并后删除分支。
