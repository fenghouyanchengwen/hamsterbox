# 仓鼠盒分享包格式 v1（草案）

| 项目 | 内容 |
|---|---|
| 负责人 | 成员五：分享包 |
| 状态 | 草案，待与 T02 及相关负责人确认 |
| 更新日期 | 2026-10-30 |

本文定义仓鼠盒分享包的文件结构、元数据、校验和导入预览行为。本文中的 JSON 字段名、格式常量和状态枚举是程序接口标识，保留英文；说明和示例中的普通内容使用中文。任何尚未确认的约定均为提案，不应视为已冻结接口。

## 1. 目标与范围

分享包用于在不同设备或不同仓鼠盒安装之间分享条目及其元数据。分享包不应包含原始媒体文件或可执行文件；允许携带经过校验的封面图片。导入前应展示预览，用户确认后才写入本地数据库。

本规范仅定义分享包边界，不替代 T02 的领域模型。条目类型、稳定标识的生成和存储方式等需与对应负责人确认后冻结。

## 2. 文件结构

分享包使用 `.hbox` 扩展名，内容为 ZIP 压缩包。建议结构如下：

```text
example.hbox
├── manifest.json
└── covers/
    └── <sha256>.<ext>
```

`manifest.json` 为必需文件，采用 UTF-8 编码且不带 BOM。`covers/` 及其中的图片为可选内容。压缩包不得包含原始媒体、数据库、脚本或可执行文件。

导入器必须防止 ZIP Slip 等路径穿越，并拒绝重复路径、加密条目、符号链接和不支持的压缩方式。以下上限是待确认的初始建议：压缩包 50 MiB、manifest 10 MiB、单张封面 5 MiB。实际限制应由实现统一配置并在导入前检查。

## 3. Manifest 格式

完整机器可读约束见 [`share-package-v1.schema.json`](share-package-v1.schema.json)。示例见 [`examples/share-package-v1/`](examples/share-package-v1/)。

### 3.1 顶层字段

| 字段 | 必需 | 含义 |
|---|---:|---|
| `format` | 是 | 固定为 `hamsterbox-share-package` |
| `format_version` | 是 | 分享包格式版本，初始值为 `1.0.0` |
| `generated_by` | 是 | 生成应用名称与版本；应用版本仅供信息展示 |
| `package_id` | 是 | 本分享包的 UUID |
| `source_library_id` | 是 | 来源资料库的稳定 UUID，不得直接使用 SQLite 自增主键 |
| `created_at` | 是 | 生成时间，使用 UTC ISO 8601 时间并以 `Z` 结尾 |
| `entries` | 是 | 非空条目数组 |

`source_library_id` 和条目分享标识应在同一资料库的重复导出中保持稳定，才能用于识别重复导入；其在现有数据模型中的存储方式仍需 T02 确认。`package_id` 则每次生成新包时重新创建。

### 3.2 条目字段

每个 `entries` 元素包含：

| 字段 | 含义 |
|---|---|
| `share_id` | 条目的稳定 UUID 分享标识 |
| `title` | 条目标题 |
| `type` | 条目类型；必须采用 T02 确认的类型值，不在本规范中自行定义枚举 |
| `description` | 描述，可为空 |
| `created_at`、`updated_at` | UTC ISO 8601 时间 |
| `resources` | 资源元数据数组，不携带原始资源文件 |
| `tags` | 本包涉及的标签定义 |
| `entry_tags` | 条目与标签的关联及该关联上的评分、短评 |
| `cover` | 可选封面描述对象；无封面时可为空 |

分享标识应可跨设备使用，不应暴露本地数据库主键。字段名称和空值规则须与 T02 对齐。

### 3.3 资源元数据

资源对象包含 `share_id`、`file_name`、`extension`、`size_bytes`、`sha256` 和 `availability_at_export`。

- `file_name` 只允许文件名，不得包含目录路径；扩展名统一为小写且以点号开头。
- `size_bytes` 为非负整数或 `null`；`sha256` 为 64 位小写十六进制摘要或 `null`。
- `availability_at_export` 取值为 `present` 或 `missing`。资源在导出时缺失时，相关大小和摘要可为空。
- 导出时资源存在的，计算其 SHA-256；分享包只记录元数据，不携带原始资源。
- 文件名不能作为资源匹配的唯一依据；导入器应结合摘要及用户选择处理匹配。
- 不得写入本机绝对路径、用户目录或其他本地路径信息。

### 3.4 标签、评分与短评

标签定义包含 `share_id`、`name`、`color` 和 `rating_enabled`。`color` 可为十六进制颜色值或 `null`。`entry_tags` 通过 `tag_share_id` 关联标签，并可包含 `rating`（1 至 5 的整数或 `null`）和 `review`（字符串或 `null`）。评分和短评属于条目与标签的关联，而非全局标签属性。

### 3.5 封面

封面对象包含 `archive_path`、`media_type`、`sha256` 和 `size_bytes`。封面文件应位于 `covers/` 目录下；导入器须验证路径、媒体类型、大小和摘要。封面缺失或校验失败时，应报告封面问题，但不得因此丢弃其余有效元数据。

## 4. 导入预览与提交

导入器在实际写入前，应解析分享包并提供条目、资源、标签和封面的预览。资源匹配状态建议使用以下稳定枚举：

- `auto_linked`：根据可靠标识或摘要自动匹配。
- `needs_selection`：存在候选项，需要用户选择。
- `missing`：本地没有匹配资源。
- `conflict`：存在冲突，需要用户决定如何处理。

用户可以选择导入全部或部分条目。用户确认前不得修改数据库；确认后的数据库写入应在一个事务内完成，发生错误时整体回滚。相同 `source_library_id` 和条目 `share_id` 的重复导入应保持幂等，不应无提示地产生重复条目。

## 5. 校验与错误处理

导入时至少执行以下校验：

1. 压缩包可读，且恰有一个根目录 `manifest.json`。
2. 拒绝路径穿越、绝对路径、重复路径、符号链接、加密条目和不支持的压缩方式。
3. 检查压缩包、manifest 和封面的大小限制。
4. 按 UTF-8 解析 JSON；拒绝重复 JSON 键。
5. 检查格式常量、版本、UUID、时间格式、必需字段和字段类型。
6. 检查条目、标签及其引用关系；拒绝重复分享标识和空条目集合。
7. 检查评分范围、资源文件名规则、封面路径及封面 SHA-256。
8. 在全部校验通过且用户确认前，不执行任何数据库变更。

错误应包含稳定错误代码和可理解的中文说明，不得泄露本机绝对路径。若发现任一影响包整体安全或结构的错误，应在修改数据库前终止导入。

## 6. 版本兼容策略

分享包格式遵循语义化版本号。v1 初始版本为 `1.0.0`。v1 导入器可接受主版本号为 1 的包，并忽略未知的可选字段；遇到未知主版本号时，必须在写入前拒绝导入。破坏兼容性的结构变更应提升主版本号。生成应用的版本号仅用于诊断，不决定格式兼容性。

## 7. 冻结前待确认事项

- 稳定 UUID 分享标识如何在 T02 的数据模型中生成、存储和迁移。
- 条目类型的确切枚举值，以及字段名称、必填性和空值规则。
- 封面采用包内嵌入（本草案建议）还是外部引用。
- 压缩包、manifest 和单张封面的最终大小限制。
- 导入冲突的可选处理策略，以及同名标签的合并或保留规则。

以上事项确认后，应更新本文件与 JSON Schema，移除草案状态，并加入经验证的 `.hbox` 样例，再将格式视为冻结。
