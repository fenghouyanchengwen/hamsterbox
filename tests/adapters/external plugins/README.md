# 外部插件开发指南

通过编写外部插件，可以在不修改主程序代码的情况下，让软件支持识别和解析更多独特的文件格式，真正实现“即插即用”的扩展能力。

## 1. 插件目录规范

为了保证主程序能够正确扫描并加载，所有的外部插件都必须以**独立文件夹**的形式存在，并存放在用户数据目录下的 `plugins` 文件夹中。

一个标准的插件目录结构如下：

```text
data/plugins/
└── archive_support/          # 你的插件文件夹（建议全小写，用下划线连接）
    ├── manifest.json         # 插件配置清单 (必须)
    └── archive_adapter.py    # 插件入口代码 (命名应与配置一致)
```
可以参考项目根目录下的 plugins/1/ 文件夹，里面提供了一个完整的“压缩包解析插件”参考。测试时，只需将整个文件夹移动到 data/plugins/ 下即可。

## 2. 配置文件规范 (manifest.json)
manifest.json 是插件的“说明书”，主程序在加载代码前会先读取它。请确保包含以下必填字段：
```text
{
    "name": "Archive Support",
    "version": "1.0.0",
    "description": "支持解析常见压缩包格式",
    "author": "YourName",
    "entry_point": "archive_adapter.py",
    "adapter_class": "ArchiveAdapter"
}
```
name: 插件的显示名称。

version: 插件版本号（建议遵循语义化版本规范，如 1.0.0）。

entry_point: 你的 Python 脚本文件名（必须包含 .py）。

adapter_class: 你的脚本中定义的适配器类名。

⚠️ 严格对应：entry_point 和 adapter_class 必须与你的实际代码完全一致，否则加载器会找不到入口并跳过该插件。
## 3. 代码实现规范
插件类不需要继承任何特定的基类，只要实现了主程序要求的 FileAdapter 接口（鸭子类型）即可
#### 具体代码规范可以参考archive_adapter.py文件，主要包括：
```text
1. 声明支持的扩展名 (必须全小写，带点号)
    如：extensions = (".zip", ".rar", ".7z", ".tar", ".gz")

2. 识别类型
   返回该文件对应的系统类型。
   注意：必须返回系统已有的枚举值（如 OTHER, IMAGE, VIDEO 等）。

3. 读取元数据
   返回文件的详细属性，系统会将此字典展示在详情页。
   无论解析是否成功，都必须返回一个字典，绝不能抛出异常。
       
   编写解析逻辑，例如解析 zip 包内的文件数量

4. 是否支持内嵌预览
```
## 4.安全红线
外部插件与主程序运行在同一个 Python 进程中。为了保证仓鼠盒的绝对稳定性，开发者必须遵守以下红线：

### 异常隔离（防御性编程）：
read_metadata 内部必须使用 try-except Exception 包裹所有解析逻辑。哪怕用户拖入了一个彻底损坏的文件，插件也只能静默失败并返回兜底数据（如 {"parse_status": "failed"}），绝对不能让异常逃逸导致软件闪退。

### 只读原则：
适配器只能“读取”文件属性。禁止对用户的原始文件进行移动、重命名、删除或写入操作。

### 禁止执行系统命令：
插件中不允许出现 os.system 或 subprocess 来调用外部程序。

### 类型约束：
数据库不接受插件自定义的类型，必须将结果映射到主程序支持的现有 EntryType 枚举中
## 测试与调试
将编写好的插件文件夹放入 data/plugins/ 目录。

启动仓鼠盒主程序。

观察控制台日志。如果加载成功，终端会输出：[Plugin] 成功加载插件: [你的插件名]。

在软件中关联一个对应的文件（如 .zip），检查资源详情页是否能正确显示你解析出的元数据。

如果遇到加载失败，请检查 manifest.json 的字段是否拼写错误，或入口文件、类名是否对应
